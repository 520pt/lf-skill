# 跨项目工程规律

这些规则来自王路飞在多个本地 Codex 项目中的重复问题，适用于跨项目判断，不替代具体项目的 `AGENTS.md` 和 `MEMORY.md`。

## 编码前思考

- 开始修改前，先写清楚用户真正要解决的问题、完成标准、已知约束和当前假设。
- 如果存在多种合理解释，列出差异；能从项目文件、日志、运行状态或已有实现确认的，先自行检查。
- 如果关键歧义无法自行确认，且错误选择会造成明显返工、数据损坏或外部影响，先向用户提问。
- 发现更简单、风险更低且不改变用户目标的方案时，说明取舍，不为了迎合原始表述而实现明显复杂的方案。
- 不把“可能以后有用”当作现在增加抽象、配置项或功能的理由。

## 简洁和精准修改

- 用满足当前完成标准的最少代码、最少依赖和最少文件改动解决问题。
- 不为一次性逻辑创建复杂抽象，不提前增加未被要求的灵活性或可配置性。
- 修改已有代码时匹配当前项目风格，不顺手重构相邻的正常代码、注释或格式。
- 只清理本次改动造成的无用导入、变量、函数和配置；原本就存在的无关死代码只报告，不擅自删除。
- 每一行改动都应能追溯到用户目标、必要的错误修复或验证要求。

## 目标驱动执行

- 把模糊的动作要求转换成可验证的结果。例如“修复输入校验”要转成“无效输入有测试、返回明确错误、正常输入仍然通过”。
- 多步骤任务使用简短计划：

```text
1. 检查现状 → 验证：确认入口、问题和当前行为
2. 修改目标 → 验证：相关测试或静态检查通过
3. 检查结果 → 验证：真实流程、最终文件、设备或服务状态正确
```

- 强制修改测试时，先补能复现问题的测试，再实现修复；重构时至少确认修改前后的相关测试都通过。
- 每一步验证失败时，先定位失败原因再继续，不要在没有新证据的情况下重复同一条失败路径。
- 任务完成的判断以成功标准和最终状态为准，不以“代码已经写完”或“接口返回成功”为准。

## 证据优先级

遇到源码、注释、日志和运行结果不一致时，按下面顺序判断：

1. 当前真实运行行为；
2. 实际抓到的网络请求和响应；
3. 当前正在提供服务的资源；
4. 当前进程配置和启动参数；
5. 持久化数据和数据库；
6. 生成文件和构建产物；
7. 已提交源码；
8. 注释、旧文档和死代码。

源码用于解释运行行为，不能在运行证据明确相反时强行覆盖运行事实。

## 从输入到最终结果

先证明一条最小完整链路：

```text
用户输入
→ 解析/校验
→ 业务判断
→ 状态或数据变化
→ 后端/系统副作用
→ 最终页面、文件、通知或设备结果
```

只证明中间接口返回成功，不等于功能完成。必须到权威状态面验证最终结果，例如数据库、真实文件、实际发送内容、运行中容器或设备界面。

## 状态和缓存

- 先定义数据的事实来源，再决定哪些内容需要缓存。
- 修改数据后同时检查内存、磁盘、数据库、前端状态、浏览器缓存和 Service Worker。
- 手动刷新不能只写磁盘而不替换内存对象。
- 生成型操作不能复用已经过期的题目、队列、选择项或配置快照，点击生成前要按当前设置重新计算。
- 默认值不能只改界面，还要检查后端默认、持久化数据、迁移和缓存失效。

## 真实参考和 UI

- 先确认要对齐的对象和范围，再实现。
- 参考图片可能只提供结构，不一定要求复制皮肤。
- 原版应用行为要通过真实操作、日志、网络或反编译结果确认。
- 构建通过只代表代码能编译，不代表布局、焦点、字体、按钮点击和最终文件正确。
- 遇到一个 UI 问题时，主动检查同类控件、同类页面和不同窗口尺寸。

## 失败、重试和幂等

涉及通知、上传、导入、保存、队列、定时任务和外部接口时，至少检查：

- 重复请求是否会造成重复数据或重复通知；
- 失败后是否留下半成品状态；
- 重试是否会重复执行副作用；
- 用户取消或超时后状态是否能恢复；
- 定时轮询是否会把同一事件反复发送；
- 手动修正后自动任务是否会覆盖人工结果。

## 性能判断

遇到“卡顿、慢、连拍慢、识别慢”时，先拆分测量：

```text
读取 → 解码 → 处理 → 编码 → 本地写入 → 跨边界传输 → 系统保存 → 数据记录
```

大文件优先传路径或在本地异步处理；不要用秒级人为等待掩盖竞态问题；后台任务失败时要有持久化重试或明确错误状态。

## 导入和识别

- 先复用项目中已经能工作的拖拽、导入、模板识别或 OCR 路径。
- 识别不能只看一个词或一个标签，要结合上下文、版式、选项、配置和历史基线。
- 横排、竖排、中文路径、空文件夹、重复文件名、异常图片和人工改动都要纳入验证。
- 识别结果要能解释来源，必要时保留原始识别结果和人工修正结果。

## 并行和构建

- 并行只适合互不共享文件、设备、端口、数据库和构建树的任务。
- 同一 MSBuild、Gradle、CMake 或其他构建目录默认串行。
- 并行任务完成后不能只看各自通过，还要做一次统一集成验证。

## 维护 lessons

一条经验只有在“根因不明显、容易复发、跨项目可复用”时才进入个人 skill。具体业务字段、临时 UI 文案、某次默认值和单个项目的接口细节，应写进对应项目记忆。
