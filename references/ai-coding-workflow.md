# AI 编程协作三层工作流

这份规则把 CodeGraph、Ponytail 和 Karpathy Guidelines 组合成一个互不重复的工作流程。它们不是三个都来重复指挥编码，而是分别负责“找准、写少、验证稳”。

## 一、三者分工

### 1. CodeGraph：定位层，先找准再动手

CodeGraph（代码图谱）用于理解代码之间的关系，不只是按文件名搜索。适合先确认：

- 真实入口、路由和启动位置；
- 函数、类、接口、组件的调用者和被调用者；
- 修改一个符号可能影响哪些文件、测试和业务流程；
- 现有实现、重复逻辑、依赖关系和潜在影响范围。

使用规则：

- 当前环境有 CodeGraph 且索引有效时，修改前优先用它定位调用链和影响范围。
- 先确认索引没有待同步文件；索引过期时，直接读取当前源码和运行结果，不能把旧图谱当成事实。
- CodeGraph 结果是定位线索，不替代真实运行、当前源码、日志和最终结果验证。
- 当前环境没有 CodeGraph 时，不等待、不自行安装，使用项目已有搜索工具、符号搜索、调用方检索和配置检查完成同样的定位工作。
- 不为了使用 CodeGraph 而改造项目目录、增加依赖或修改项目配置，除非用户单独提出。

### 2. Ponytail：范围层，只写必要代码

Ponytail（极简实现原则）用于控制代码规模和复杂度。选择方案时按下面顺序判断：

1. 这个需求是否真的需要新增代码；
2. 项目里是否已有可复用的实现；
3. 标准库是否已经能解决；
4. 平台原生能力是否已经能解决；
5. 已安装依赖是否已经能解决；
6. 最后才新增最少代码。

执行规则：

- 不新增未被要求的抽象、接口、工厂、配置项、兼容层和预留功能。
- 不为了“以后可能用到”提前搭脚手架。
- 优先删除不必要的代码，避免用新代码包住旧问题。
- 修复问题时先找共享根因，优先在所有调用方共同经过的位置修复，不在每个调用方重复打补丁。
- 极简不等于牺牲正确性：输入校验、错误处理、安全措施、数据不丢失、无障碍和用户明确要求的功能不能被省略。
- 非简单逻辑至少留下一个最小可运行检查；简单的一行修改不为了凑数增加测试。

### 3. Karpathy Guidelines：执行层，改完必须验证

Karpathy Guidelines（面向 AI 编程代理的四项工作准则）负责把修改过程变得稳定、可复核：

- **先思考**：先明确目标、约束、假设、风险和完成标准；
- **简单优先**：选择能可靠完成目标的最小方案；
- **精准修改**：只改与任务有关的代码，不顺手重构和批量格式化；
- **目标驱动执行**：修改一步、验证一步，直到最终结果达到完成标准。

它与 Ponytail 的区别是：Ponytail 主要限制“写多少”，Karpathy Guidelines 主要约束“怎么稳定地完成并证明完成”。

## 二、统一执行顺序

复杂开发、修复和重构任务按以下顺序执行：

```text
明确目标和完成标准
→ CodeGraph 或项目原生工具定位入口、调用链和影响范围
→ 选择 Ponytail 的最小可行方案
→ 按 Karpathy Guidelines 做精准修改
→ 运行最小相关检查
→ 验证真实流程和最终状态
→ 只报告本次改动、验证结果和剩余限制
```

## 三、不同任务的最低要求

### 只读分析

- 不修改文件、不改代码、不改变外部状态；
- 先说明分析目标和证据来源；
- 结论区分“已确认”“合理推断”和“尚未验证”。

### 普通代码修改

- 修改前确认入口、调用方和已有实现；
- 保持最小差异；
- 至少执行相关测试、类型检查、静态检查或可运行验证中的一种；
- 交付前说明实际验证结果。

### 复杂流程或高风险修改

- 先画出输入、处理、状态变化、副作用和最终结果链路；
- 检查重复执行、失败恢复、超时、取消和重试；
- 不能只用接口返回成功作为完成依据，必须检查权威状态面。

## 四、冲突处理

- 用户本轮明确要求优先于默认极简方案；
- 项目专属规则优先于个人通用规则；
- 真实运行结果优先于图谱、源码注释和旧文档；
- 极简原则不能覆盖安全、数据完整性、错误处理和用户明确要求；
- 定位工具不可用时使用普通搜索，不把工具缺失当成任务阻塞；
- 验证发现问题时继续定位和修复，不把未验证的中间结果当成最终交付。
